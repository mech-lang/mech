Independent candidate: borrow operation identity during validation
Patch: borrowed-operation-validation.patch
Scope: Core only, src/core/src/function/specialization.rs.
Status: unapplied; no compile, test, or benchmark run.

Mechanism
ResolvedOperationDescriptor::validate currently clones the canonical name and full operation contract solely to call Self::new. That constructor checks only whether the name is empty or hashes to a different OperationId. The patch makes validate perform that same borrowed check, and makes new construct the owned descriptor then call validate. There is one authoritative check, no unchecked constructor, and no newly cached permission.

Exact R56 target
30 requests / 657 requested bytes in ResolvedOperationDescriptor::validate beneath plan_call_memory: 9 requests at the seed record and 21 at the singleton matrix. Isolated R56 prediction: 8,773 -> 8,743 requests; 98,243,843 -> 98,243,186 requested bytes. Test real family disappearance; actual elapsed/instructions remain unmeasured.

Error/ordering audit
- validate keeps empty-name short-circuit before computing OperationId::from_name.
- Same RuntimeOperationBindingMismatch type, operation=Some(id), exact reason format, message=None, and with_compiler_loc attachment. Its compiler-location line naturally moves to the shared borrowed check; it remains this source file and is populated for both new and validate. Do not assert an obsolete numeric source line.
- new still converts canonical_name into Box<str> before checking it and already owns the contract argument. Struct assembly is infallible and invokes no user code; invalid input still returns the same error before any successful descriptor escapes.
- validate still does NOT validate operation contract semantics. It previously cloned that contract but never inspected it. Declaration/storage/type checks remain where plan_call_memory and catalog binding already perform them.
- Do not remove plan_call_memory's call to validate. ResolvedOperationDescriptor fields are public, and BoundCall::syntax_directed/artifact_operation_for_target do not universally establish a name/ID certificate. Existing public mutation must continue to be rejected dynamically.
- No budget charge or reservation is moved/removed. Current planning entry validation occurs in exactly the same position before arity/target/storage checks. Only transient success-path copies disappear.
- Existing alloc/no_std imports suffice; patch introduces no std-only dependency or new feature gate.
