Key result
The broad 1,554-request metadata family contains several smaller ownership mistakes that can be removed independently of a persistent prepared-plan design. They are ordinary cloning and discarded temporary construction, not changes to allocation contracts. The accompanying construction-ledger.py reproduces exact event-family counts from the R56 full census. The seven enumerated stack families are disjoint in that census; however their removal by a larger prepared-binding change would overlap, so do not add predicted gains across implementation proposals.

1. Unsealed binding transfer: 72 requests / 5,404 requested bytes.
Engine resident/native_semantics.rs:221-248. Every call clones BoundCall before testing whether the optional private scalar seal exists. For CompositePack and MatrixHorizontal there is no candidate, so the original BoundCall is dropped. Move it into the kernel. Keep with_bound_call's clearing of witness/accounting and the accounting restoration. The sealed branch still retains both copies as before. See unsealed-binding-transfer.patch and .txt for focused parent-failing test and acceptance.

2. Already-owned refinement plan: 149 requests / 15,286 bytes.
Engine memory_planner/turn.rs:459-534 consumes TurnMemoryPlan but immediately clones its owned optional CallMemoryPlan. Use plan.call.take(); refine using that moved call; put it back unchanged on the branch that does not refine. On errors the whole input plan was already consumed, so no external owner sees the intermediate None. KernelCostEstimate::turn_plan at resident/budget.rs:1829 retains the active Arc and supplies a separate plan clone, so failure still leaves active/current publication intact. This removes an entire deep call copy without changing derivation, charge order, dynamic facts, limits, or allocation placement. Test successful refinement against the unchanged planner, zero-demand/no-final-output no-refinement, call=None, multiple outputs, overflow/missing witness/limit denial, active original plan unchanged and success->failure->retry.

3. Discarded allocation list: 4 requests / 3,840 bytes.
Engine memory_planner/turn.rs:638 copies the allocations into the scoped call. Its only callers at :208 and :532 immediately continue placement/growth, then overwrite call.allocations at :224 or :545. Neither reads the intermediate allocation list; no code can observe it. Remove that first assignment/argument and retain the final post-placement assignment. This is very small, but a literal allocate-copy-free chain proved by source and four exact +348 return-offset census groups (1,152+1,152+768+768). Keep transaction remapping.

4. Validation through construction: 30 requests / 657 bytes.
Core function/specialization.rs:603-604 validates an operation by cloning its name and entire contract into Self::new. The constructor at :529-553 only tests empty name and name/ID agreement. Factor a borrowed name/ID check shared by new and validate, preserving error kind/message/compiler location behavior. Avoid removing validation from plan_call_memory: BoundCall construction does not universally validate publicly mutable ResolvedOperationDescriptor contents. Test valid, empty-name, wrong-ID descriptors and contract variations; census should remove precisely this subtree. This is a general improvement for all planner consumers, not a constructor-specific cache.

5. Borrowed planner views: two separate current chains, 151 requests / 15,310 bytes plus 157 requests / 19,238 bytes.
(a) Engine memory_planner/turn.rs:116 deep-clones a CallMemoryPlan to override output regions and temporarily clear target limits in derive_turn_call(:608-620). TargetMemoryProfile owns only fixed fields; current regions are flat values. A borrowed call + local target/region view can invoke the same Core current-call derivation and avoid copying bound types/ports. Preserve current error order and reapply exact limits to final result. This is preferable to putting mutable authority in a cross-invocation cache.
(b) Engine resident/general/native_collection_invocation.rs:654-674 clones self.memory, clones its allocations again, allocates call_nodes and calls boxes, and constructs a one-call ProgramMemoryPlan solely to call plan_turn_memory. A borrowed one-call plan view can preserve the same common planner, remapping NodeScratch owners while it makes the actual turn allocation list. Do not fork a second budget planner.
These views are moderate changes; they can be developed after the trivial owned-copy removals. Existing proposal to prepare immutable seed binding remains useful, but it need not be the first path to measurable savings. Stage and retain only immutable type/geometry; dynamic current limits, actual values, account membership, funds, errors and publication stay in invocation.

6. Existing fixed constructor not reused: 11 requests / 1,565 bytes.
Engine resident/general/native_collection_calls.rs:89 always sets activation_fixed_shape=false. CompositePackPlan at resident/composite.rs:297-301 therefore marks the all-scalar seed's already-bound constructor as non-fixed. composite_pack :1345 onward rebuilds it with current_constructor(:1070). A zero-parameter schema's ShapeInstance tape cannot vary; the prepared constructor already exists. This is a possible narrower immutable-geometry reuse, but simply flipping activation_fixed_shape is NOT sufficient: the current code then drops normalization work/byte/node charges (:1140 onward) and can alter error precedence. A safe physical reuse would preserve original conservative normalization charges and current key/shape checks, then borrow the immutable constructor. Lower priority than ownership moves.

Prepared-call design caveats
- Preparing a binder early must not raise an error on an unselected branch that previously failed only when called. Treat precomputation as optional: derive only successful immutable geometry; declined/failed preparation retains the ordinary current binder.
- Exact maintained factory provenance is already established by native_collection_templates::select_leaf (:719-763) and private native_collection_semantics registration. Do not generalize this to arbitrary catalog replacement kernels with mutable retained state. The two selected constructors' retained plans are immutable, but eligibility must remain tied to the maintained path.
- Fixed shapes do not imply fixed input values, retention membership, available budgets or final publication. Closed-schema metadata reuse has no authority across those boundaries.
- Binding/invocation envelope charges and reservations can conservatively stay unchanged while physical metadata allocations disappear. That keeps the pinned work receipt and finite-denial behavior before revisiting resource contracts.

Measurement policy
All request counts above are observed R56 stack attribution. They are not measured improvements until the proposed code is run. The seed sites total only 33/1314 sampled weights in the supplied review; do not predict a large elapsed gain from request count. Measure instructions, cycles and matched elapsed independently and retain adverse results. Any larger immutable-plan change subsumes some of these chains; avoid double-counting savings.
