# Read-only audit findings retained for review

These investigations are pinned to R56. They are prospective mechanisms, not measured R60 improvements. No production implementation, compiler build or benchmark execution was performed by the audit. The native vector code-generation experiment and R59 cached-key change are documented separately.

1. **Unused imported constants:** exhaustive semantic-read inventory identifies309 of500 constants with zero reads, including all indirect/prepared-template consumers. Their current import family predicts618 requests/66744 bytes; this overlaps the existing1000-request constant family. A safe implementation must preserve original work and finite admission order, snapshot-node accounting, generation effects and failure cleanup. Static zero-use alone does not prove import-registration invisibility to same-storage aliases. This remains a design/proof task, not implementation-ready permission.
2. **Repeated TLS lookup:** the42 exclusive R56 TLS sample weights include6 mimalloc weights. Existing charge_in_context already accepts a context reference. Smallest candidate combines duplicate TLS entry within each meter operation without reordering individual charges or caching authority. A larger lexical handle must read current limits on every debit, permit reentrancy and never escape. No allocation reduction is predicted; actual emitted calls, instructions and elapsed must establish value.
3. **Budget first-violation API:** an unapplied minimal patch replaces two all-violation-vector queries by the existing first-violation API. Existing Core tests establish complete order equivalence across2048 policy subsets, full-width overflow and no-violation cases. Existing Engine scope/nested-cap/prefix/worker tests remain the acceptance set. Check current production state before applying: this file records the audit proposal, not a claim it remains absent.
4. **Canonical-to-private continuation transfer:** an alternative to the known840-request first-change intermediate target is preserving an exclusively held intermediate's shape/data/registration while moving it into the private continuation. Only the unpublished wrapper would be replaced. Corrected ceiling is3×168=504 requests; it overlaps the known intermediate target. Existing live/weak alias, first-change comparison, same-account charge and failure-prefix conditions must be proven; no saving has been measured.
5. **Repeated footprint dispatch:** prepared frame footprint measurement checks kind and then dispatches through Core's generic sequence visitor. R56 sample attribution has19 exclusive frame weights in the relevant value/sequence visitor region. A shared Core packed-header footprint witness might avoid repeated traversal/dispatch, but Engine must not duplicate Core's layout formulas or treat an immutable schema fact as current ownership/admission permission.

The count-only proposals cannot be ranked as elapsed gains. Sample weights are neither exact call counts nor retired instructions. Cached schema keys, unique-root reuse, completed-child cleanup, shared numeric shadows, last-use private transfer, registration-link locks and private-publication lock removal are already completed work and are not presented as new opportunities.
