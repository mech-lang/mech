# Native pieces around multiple ordinary children

R79 is implemented, qualified and retained. The [current-status owner](../../../docs/design/native-compression-status.md) records the 9.79% elapsed /10.23% instruction reduction and code/stack tradeoff. Exact raw data is external and hash-indexed; the original design/baseline below remains historical evidence.

The real complete compressor contains a reached parent with nine immediate
children: one collection and eight Tail calls. At R78 it is diagnostic iteration
25, with 818 directly owned source blocks, seven unsigned-array carrier fields
and sixteen scalar fields. These identities locate the witness; production
eligibility must use validated graph/type/ownership properties.

The existing composition pass requires exactly one immediate Tail child, so it
rejects that parent before proving any acyclic pieces. The new maintained fixture
`numeric-multiple-children.mec` has a collection, sequential writes, a nested
private-frame parent, current Boolean state and recursive parent visits.

At unchanged production `0eb0c3d9d8a59fbf14b4ec3563944a276b56b8a4`, the original
and decoded semantic/error/alias/recovery control passes. The six-dimensional
finite exact/one-short boundary control passes. The positive parent-selection
and executed-piece test fails with the exact missing multi-child inventory.
The baseline test build uses the retained GPU opt1, warnings-as-errors and
unchanged dependency graph; all three tests execute (two pass, one expected fail).
Raw commands and logs belong to the external evidence packet, not source Git.

Generalize the existing parent inventory to multiple ordinary child boundaries.
Child initialization, exit, publication and mutation stay ordinary. Each acyclic
piece uses the existing frame/provenance/liveness/admission/numeric proofs and
reacquires current owners and views. No loan, private owner or prepaid fuel may
span a child. Existing result-field mappings remain diagnostic proof evidence,
not permission to retain a child view.

Nested composition must retain exact child-continuation checks. The existing
structured loop ancestry and active progress already describe suspended calls.
Keep the single scalar pending-edge marker; on a nested call, verify its expected
ancestor and on return restore that ancestor from immutable graph facts. Do not
allocate a second continuation stack, executor or resource ledger. A piece may
run within a suspended ancestor only when its marker matches that exact ancestry.

Acceptance covers current buffer/Boolean visits, sequential and nested calls,
unselected/empty children, assertion/arithmetic/read ordering, unchanged prior
publication, input aliases, exact/one-short resources, retry and final zero managed
ownership. Reconstruct the same inventory from independently loaded images.
Then measure real executed host-operation counts, instructions, allocations,
code/stack and matched complete-call timing. Selection-count growth alone is not
an optimization result. Keep managed-projection extension and first-admission
registry ownership as separate experiments.
