# Prefer preserved integer registers in the checked root

Measured pool: the qualified 64,444 B encoder has a 47,428 B checked root, 11,857 native instructions and 338 calls. The root contains 2,106 direct-SP ldr, 857 str, further paired/unscaled stack operations and 2,084 mov instructions. Its post-cleanup IR has seven explicit stack slots totaling 560 B, 21 stack stores, seven stack loads, 452 indirect stores and 297 indirect loads, while its native frame is 3,104 B. Native stack traffic substantially exceeds source memory operations. These are static size counts, not runtime attribution.

Work removed: the normal AArch64 register environment prefers x0-x15 and treats available callee-saved x19-x28 as nonpreferred. For this opt-in memory-backed checked root, reverse only those integer preference sets during register allocation. Keep the exact union, pinned/scratch exclusions, call clobbers, constraints, frame/unwind construction and register-allocation checker. All other functions retain the existing environment.

Expected effect: keep more values live across the root's calls in preserved registers, reducing spill/reload instructions and possibly construction cost. Current root already saves all ten preserved registers, so there is no obvious new root prologue budget. The actual tradeoff must be measured; temporary values can also receive worse placements. Seek a material code reduction, then maintain or recover 81/81 Roc and 62/81 C wins rather than rejecting a nearly qualified smaller worker immediately.

Correctness boundary: this is an allocation preference, not a new register, changed ABI, unchecked operand, source rewrite or weakened validation. The new function attribute defaults off and clears normally. Gate its effect to Apple AArch64 and apply the flag only to eligible memory-backed diagnostic roots. Compare the default artifacts exactly, execute a retained-JIT test through calls/outputs/sentinels with both preferences, and keep SSA/regalloc checks. Any changed worker requires complete output/failure/cleanup checks and full both-order peer qualification. Remap stale native layout selections by existing identities if needed rather than discarding a valid mechanism.

Stopping rule: one prototype, baseline identity check, native-size/stack and focused runtime screen, then price complete build time. If material but a narrow runtime miss appears, attempt a bounded repair. Preserve adverse variants. If size does not improve materially or no plausible repair remains, record that decision and return to the current whole-project board. Do not replace the qualified recipe until all required runtime gates pass.
