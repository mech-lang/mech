# Broader improvements after the adaptive-check experiment

The objective remains 1× libdeflate across all 81 cases, while retaining every named 81 Roc / 63 C win. A barely losing input is an acceptance check, not the sole optimization target. Keep size, stack and complete source-through-final-link time alongside runtime results.

1. **Keep hot matcher state in registers.** The qualified HF-U32 match collector executes 21,120,522 stack loads and 6,553,945 stack stores on random 1 MiB. Current selected-owner samples place 72.9% of its encoder tree in the matcher. The allocator's spill costs use approximate loop depth; its existing measured layout profiles do not inform those costs. Test generic, optional spill weights from mixed-case execution counts, with complete lowered-code identity checks and the symbolic allocation checker. A smaller or faster instruction trace is insufficient: measure uninstrumented complete calls on trained and held-out inputs. Do not project a speedup from the stack-count total or sample share.

2. **Remove repeated matcher representation and checked-state work.** Complete comparable Mech/C search, skip, tree-step and prefix-byte counts. The DP pass, node-update, match-record and candidate-length counts already agree on all nine measured inputs. Matcher work has not yet been shown equal. If semantic work agrees, target repeated base/hash/state loads and checks with generic ownership, alias and range proofs; if it differs, test an ordinary-Mech algorithm change with exact compressed output as the initial contract. The existing immutable-current-read and spill-pairing work must be included in every control. C also uses 16-bit node positions; Mech rebasing already uses four-vector SIMD saturation, so neither is an absent capability to implement again.

3. **Amortize temporary ownership setup where it matters.** Natural 1 KiB records 65 Mech payload requests, against C's compressor context plus output. Its coarse diagnostic gap is around 14 microseconds; mapping/unmapping alone does not explain it. Classify remaining temporary payloads and lifetimes before selecting shared storage or fewer ownership boundaries. Canonical lookup matrices already live in readonly object data. Preserve finite admission, exact errors, resource observations, aliases and cleanup, including injected failure/recovery. Existing per-operation clocks perturb short calls and are not a budget of removable time.

The conditional adaptive-block source is retained for combinations. It removes millions of matcher instructions on large random input but leaves its measured time flat and slows distribution change. That result argues for measuring dependency and memory behavior, rather than pursuing instruction-count reductions alone. The search/skip source split is also retained: projection ordering repairs native admission, but its larger code, slower builds and overlap loss still need repair.

Use the nine mixed cases to explain a mechanism, the 21-case balanced panel to discover effects across families, and both full 81-case orders to establish a new retained score. Small slowdowns are acceptable when named wins survive. Confidence support is reported separately. Preserve adverse observations and promising partial gains for combinations.

Both register models retain every 81 Roc / 63 C named win in both full point orders. Next, combine the mechanism with the smaller original 2,719-line source, using an exact VCode match or a fresh capture. Then census transparent blocks that forward arguments: the normal matcher has 2,153 VCode blocks, 435 distinct resolved label offsets and 202 machine basic blocks. Shared labels alone do not establish which blocks can be removed. Test whether generic SSA forwarding reduces construction and liveness work while preserving typed block arguments, errors and finite admission. Retain the current broad gains throughout that work.
