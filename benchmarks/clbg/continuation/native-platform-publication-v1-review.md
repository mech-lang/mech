This additive source packet connects the six-language importer to the existing
verified platform filter. The tested native importer and historical hundred-row
platform adapter remain unchanged. No source, timing, dataset or Site is changed
by authoring this packet.

native_platform_metadata_v1.py runs after the whole-six importer and before
publication_endpoints_v1 pruning. It requires the identical admitted packet and
metadata artifacts, twenty current profiles and ninety full processes for each
language, actual compiler/runtime receipt bytes, the exact JSON-pointer saved
value/encoding, and counted source/full measurement provenance. It stages every
record and rechecks all file pins before committing. V is rejected in languages,
programs and benchmark groups. Vendor/toolchain proof files may be external;
public receipt/provenance artifacts remain within CLBG. It does not infer a
platform from an extension, source label or upstream benchmark ID.

The four new fixtures exercise complete120 staging without measurement changes,
wrong actual version/pointer/encoding/digest, partial cohort/backend/V/memory
contradictions, and a late provenance conflict. A serialized actual runtime
value positive case is also covered. qualify_native_platform_v1.py runs these
four methods from fresh source snapshots under the common mutex, reusing the
qualified immutable native-importer/unittest dependency evidence rather than
repeating its sixteen successful fixtures. It preserves actual IDs, raw output
and terminal pins on success or failure. These are adapter fixtures, not actual
language metadata qualification or publication.

platform-filter-proposal-v3 preserves the previously passed platform mapping and
selection assertions. Its additive memory path consumes verified metadata
provenance from the new adapter; invalid explicit memory evidence stays unknown.
The retained older languages keep their established legacy memory policy when
no explicit measured memory record exists. qualify_platform_frontend_v3.py
requires the actual new four-fixture receipt plus the old passed v2 frontend
receipt, then runs the extended assertions with the pinned Node under the mutex.
It uses the qualified controlled toolchain environment, never a complete copy of
the host environment. No v3 frontend queue until actual native adapter fixtures
have completed and their receipt is consumed.

The unqueued v3 runtime mapping also covers verified native JIT/interpreter paths
and a verified JavaScript runtime with explicitly unknown execution mode. The
last category does not infer historical V8 JIT from an uncaptured NODE_OPTIONS
environment. Exact runtime/report/source/command provenance remains mandatory;
separate legacy metadata qualification still precedes any actual annotation.
