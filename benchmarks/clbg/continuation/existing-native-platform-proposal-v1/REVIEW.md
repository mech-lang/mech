This additive source proposal covers the current 133 selected C, C++, Rust,
Mech AOT/JIT/resident, Julia and JavaScript rows. Ordinary saved JSON/source
schemas were inspected; no hashing, qualification, fixture, native-image
inspection command, benchmark, retiming or queue ran. The original 100-row
Java/Erlang/.NET qualifier, new-language metadata, source/count/sample/report
bytes and current frontend packets stay unchanged. `routes.json` is false until
the separate actual historical evidence qualifier completes.

The concrete frontend gap is that native-aot exists but native-jit and
native-interpreter do not. Root owns additive mappings for these two and
javascript-runtime (execution unknown). The first two retain Native platform
while distinguishing explicitly recorded compiled-at-startup modes from the loaded typed
interpreter. JavaScript platform can be proven independently of a missing
legacy execution-mode fact. Legacy NODE_OPTIONS was inherited rather than
captured by compact/fast runners, so these records cannot invent a new V8 JIT
claim. This is an evidence constraint, not a change to their saved samples.

Retime records have programs as a list, source.paths/source.sha256, actual
compile_command and command, command_assets plus a top-level asset_hashes map.
Native application hashes can therefore come from the exact original asset map
rather than an invented absent binary_sha256 field. Julia's retime map records
the resolved original binary `/private/tmp/mech-clbg-julia/julia-1.13.1/bin/julia`
with SHA `81e48f60e1d484c6fb2ea64e7cd3986190ff0bb5d5125b66f51e8d793325e3a9`.
Compiler/runtime version text must come from its original saved receipt/report
and actual command binding, never today's executable. Upstream notes and
program IDs are not local compiler evidence.

Regex/Pi and signed-division confirmations instead preserve
executable_sha256/compile_command/command for native C/C++/Rust rows. Their
confirmation arrays can contain seven samples. Reconcile exact displayed
samples with the selected report, and source/build metadata with its separately
named source_report or original report. A median, source hash or command alone
cannot join ambiguous records. Cargo rows need their preserved manifest/output
and dependency-lock routing; source extension is not native-platform proof.

Mech AOT is split across shared-products replication/summary, function-
application builds/timings, work-audit builds/timings, floating-CDF, additional-
languages timing and the exact array-state full manifest/report. In particular,
Mandelbrot's currently selected scalar11/five16 rows must use their actual
array-state sources and binaries, not older compact/SIMD controls. Each route
must bind actual source, native object/link/compiler receipt and executed native
artifact. No global current Mech compiler hash describes all historical rows.

The report schemas differ and need explicit selectors: work-audit/additional-
languages/floating-CDF use program dictionaries; application timings use a list
and application builds nest each benchmark's before/after builds; shared-products
replication uses a list with some control rows lacking source fields, so its
summary control_sources and original native metadata must be joined by actual
ID/binary identity. Array-state report.profiles contains timing summaries keyed
by its original short ID, while its manifest.profiles holds the complete explicit
public key/source/binary/command. The report's manifest SHA and each attempt bind
the two. Do not synthesize a missing source or equate a displayed ID suffix to a
historical selector. The generic proposal extractor leaves such unresolved
routes diagnostic until this explicit source/build selector is reviewed.

Retime also pins each original benchmark report in original_reports and names
the exact original_report per row. Those original receipts can establish
compiler/runtime text for retained metadata, but retime's own command/assets
and actual sample array remain authoritative for the retimed measurement. The
source/runtime observations from an original report must be explicitly joined
to the reused asset; they are not substituted for the retime sample array.

Platform, execution mode and historical executable-byte identity are independent
confidence fields. Root's policy permits an actual preserved runtime
version/command/report observation to prove platform when its corresponding
cohort producer/source/sample binding is established. Missing bytes or execution
certainty remain explicit facts rather than forcing a proved runtime platform
to unknown. A missing cohort-bound runtime observation still prevents platform
qualification. Mode-specific native-jit/interpreter require actual saved mode
evidence; generic native-runtime/execution unknown is proposed for Julia records
without that mode evidence.

Julia regex/Pi and JavaScript regex reports contain saved version/command/source
and sample records but no historical executable SHA in those rows or their
listed runtime version fields. An older report's equal path/version is not a
byte-identity reuse declaration. A qualifier should locate an explicit original
runtime snapshot/reuse receipt if present; otherwise retain
missing-historical-runtime-binary-binding and the original version provenance
separately from proved platform confidence.
Saved Node platform proof and execution proof are distinct; javascript-runtime
may remain execution unknown even when exact original runtime/source pins are
complete. Neither engine/platform nor mode is derived from a filename.
