The difference is representation of the workload argument. Original binarytrees/fannkuch producers saved a base Java command and appended N during execution. Original nbody saved literal50000000. The retime producer normalizes the saved full workload token to{n}, or appends{n} when a numeric benchmark had no token; stdin K/revcomp commands receive no token. The saved retime.protocol.workloads records the actual small/full sizes. Launcher, flags, classpath, main class, compile command, mode and source hashes remain exact. Both old and new commands must be retained; original samples/versions are never attributed to the new samples.

V2 admits only that precise workload-bound command lineage: Java arguments after its single -cp/classpath/main position must be empty, the saved full N or{n}; stdin forms must have none. The new command must equal the unchanged original prefix plus the one appropriate template. Wrong N, extra flags, changed launcher/classpath/main, changed compile/mode/source or Boolean workload sizes reject. The first existing Java fixture method now covers these real command shapes and corruptions, keeping the same exact six method IDs required by the adapter.

The two K Java profiles use a colon-separated directory/JAR classpath. V2 parses its distinct absolute entries and checks javac's output directory plus its exact shared compile/runtime classpath. This changes no artifact exception: every class directory and JAR still needs the saved retime command-asset pins. The retime K rows recorded only the launcher because its old command_assets helper treated the combined classpath as a single path; their old reports retain class hashes but the retime inventory lacks those class/JAR pins. If no authoritative saved dependency evidence exists, those rows remain verified:false with a concrete unresolved reason. Present-day hashes or today's runtime versions cannot fill that historical gap.

Outputs retain the v1 schema: exact100 annotations, six actual passed fixtures, explicit unresolved records, source/report/sample/runtime provenance and unchanged dataset.
