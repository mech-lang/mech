# Proposed original Erlang owners for the five Gleam helpers

Source-only policy proposal; no parser, hash, fixture, compile or count has run. The old `loc_probe.erl`, its qualified21-source receipt and all measured Erlang records remain unchanged. Its physical-row plus expression-sequence metric is preserved as legacy evidence. It does not establish all independent written owners in these new helpers. Nim owns the additive implementation and root must review its concrete event projection and actual fixtures before counts can become canonical proposals.

The exact selected authored originals are `gleam-comparison/20261012/support/{clbg_io_ffi,clbg_process_ffi,clbg_regex_ffi,clbg_vector_ffi,clbg_runner}.erl`. Every profile uses the originals plus its byte-equal measured compiler-input aliases. Generated Gleam Erlang, abstract forms and BEAM are compiler provenance, not replacement application LOC. Generic I/O, process, vector, regex and dispatch glue remains fully counted.

Original-source scanner tokens and parsed forms must agree on names, clause order, body order and exact source coordinates. Reject lexical/parser errors, including error forms inside an otherwise successful epp result. Comments, strings, quoted atoms and character literals preserve offsets and cannot introduce keywords or separators. Preprocessor/include/record/parse-transform forms outside this selected grammar require separate input and owner proof; an epp expansion alone cannot stand in for the authored source. Unknown syntax is diagnostic.

Proposed owner policy:

- Each complete `-module(...)` and `-export(...)` directive is one owner. Their argument/export separators and terminating periods are structural. Wrapped literal/data rows retain the canonical physical-row policy; tuple/list/call/formal/guard commas do not create statements.
- Each written named function clause has its own header through `->`, with patterns, destructuring, arity and optional guards structural. Its body exposes every written independent expression. `;` separates clauses and `.` terminates a form; neither punctuation token is an additional keyword closer. No arbitrary call body is folded into a one-unit pure definition. A future scalar-only definition exception would need its own resolved source proof and fixtures.
- Each body match/binding, send, call, return value or other expression statement is an owner. Multiple `=` operations in an expression retain independent written matches; `=` in a proved function/arm pattern is structural. Inline and expanded forms must expose the same owners. Nested ordinary calls and their data arguments remain in their containing expression, while nested callable/control/block bodies are traversed.
- Each anonymous `fun` has a header, each clause/body expression and its actual written `end`. A containing call or initializer prefix may combine with only its first directly nested `fun` or `case` header, using disjoint event spans. The callback's body and close remain independent. Additional callbacks, prior independent effects, subsequent writes and all nested callable/control bodies retain their owners. A named function header or outer arm/control header does not combine with a nested callback/control header.
- A `case` owns its selector header through `of`, every pattern/guard arm header through `->`, every arm-body expression and its written `end`. A `receive` independently owns its keyword header, every arm header, every arm-body expression and `end`; it is scheduling work and receives no scalar-value waiver. Nested `receive` stays independent of its enclosing arm header.
- For the actual runner, `try benchmark:main() of` is one selected try header including its single source expression. Its success arm header/body and exception arm header/body expressions remain independent, followed by one written `end`. The first exception arm's header includes the introducing `catch` keyword and its exception pattern through `->`; later exception arms own their own headers. Multiple independent try expressions before `of`, `after`, bare catch expressions, timeout clauses or other unselected forms must be exposed by an explicit new rule or diagnosed; they cannot be hidden under this one-expression try-header rule.
- A selected `begin ... end` block used by fixtures owns its real header, every body expression and written close. It cannot masquerade as tuple/list/call data. Unselected comprehensions, `if`, `maybe`, receive timeouts, named funs, records, binaries/maps with unproved executable contents and dynamic macro scopes remain diagnostic until independently supported. The five current helpers do not need those forms.

Source-specific owner checks:

| `clbg_process_ffi.erl` | `start` header; `Owner`/`Tag` bindings; initializer plus first fun header composed once; callback send body and fun end; returned tuple; `join` header; outer receive, both outer arms, nested receive, both nested arms, each return/error expression and both written receive closes. Pattern variables and tuples are structural. |
| `clbg_regex_ffi.erl` | `compile` header, successful compile-result match and returned pattern; `search` header, real case selector, all three arm headers, each tuple/error body and end. Pattern and returned tuple separators are structural. |
| `clbg_vector_ffi.erl` | Both function headers and their actual `element`/`setelement` value-producing call bodies. Argument arithmetic is inside the containing call; no application body disappears through a generic BIF purity label. |
| `clbg_runner.erl` | Module/export, main header, try selector, success arm/exit call, exception arm, error-output call, failure exit and real end. Preserve its source inventory role and count when it is in a measured compiler bundle; no unrecorded stream-launcher exclusion. |

Meaningful fixture obligations for the additive producer:

- Preserve the old five sequence/data observations separately; their old numeric metric must not be relabelled as the new owner metric.
- Compare inline and expanded `Pid = spawn_monitor(fun() -> Owner ! work() end)` fragments: one containing-prefix/fun header, one send body, one close. Adding an independent callback-body effect must add its own owner; passing two callbacks must retain both sets of callable owners.
- Compare inline and expanded `receive {tag, V} -> V end`: receive header, arm header, value body and close. Add a second arm and nest a receive under one arm; verify all outer headers, inner headers, bodies and both closes without overlapping spans.
- Compare packed regex-like case arms with expanded arms. Pattern tuple commas and returned tuple commas stay structural; adding `io:format(...), Return` inside one arm adds an independent body owner. An outer arm header must not combine with the nested case/receive header.
- Verify actual runner try/success/catch/close spans, including the two independent catch-body calls. Put keyword/arrow text in strings, quoted atoms and comments and prove it cannot change owner selection.
- Reject malformed original source/error forms, unknown preprocessing and unselected executable scopes in literal/data owners. A parse success, five legacy cases or a nonempty AST is not independent source-owner qualification.

The official [OTP29.1.1 expressions reference](https://www.erlang.org/doc/system/expressions.html) supports the selected clause, fun, case, receive, match/send and try syntax. The [module reference](https://www.erlang.org/doc/system/modules.html) supports the authored directives. These are syntax sources; the counting policy above is an explicit conservative proposal, not an OTP runtime or line-count claim. Numeric helper totals remain null until the actual source-bound owner receipt and independent semantic review exist.
