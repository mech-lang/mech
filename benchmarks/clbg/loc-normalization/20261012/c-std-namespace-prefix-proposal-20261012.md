# First-stage std namespace-prefix gate

The new unhooked `c_std_namespace_prefix_gate.py` implements a source-wide retained gate. `test_c_std_namespace_prefix_gate.py` contains 11 proposed pure-helper methods and three proposed integration methods. Neither source was imported, compiled, or executed. `c-std-namespace-prefix-integration-proposal.patch` is a new unapplied patch stacked after `c-preprocessor-type-macros-integration-proposal.patch`; no live core, queue, or frozen job was edited. The patch also proposes forwarding original/literal metadata in the existing std integration fixture helper.

A full-string imported `std::vector` entry alone does not establish the actual `std` qualifier. A source namespace alias or source type alias can nominate a different lookup context whose `vector<int>` is a value template, making a packed-looking prefix unsuitable for declaration promotion. [Qualified lookup](https://eel.is/c++draft/basic.lookup.qual) resolves that preceding context; [namespace aliases](https://eel.is/c++draft/namespace.alias) are independently written owners. Ordinary value-only names are ignored by the qualifier lookup described there. This first gate conservatively retains value/formal/function cases too, but does not assert that each value named `std` semantically hides the namespace.

`collect_std_namespace_prefix_gates(cleaned, 'cpp', owned_namespace_import_spans=..., protected_literal_spans=..., protected_directive_spans=...)` consumes a checked, position-preserving mask and returns diagnostics plus `blocked`; `per_use_scope_proof` is explicitly false. Every unprotected written `std` token must be actual `std::` qualification or fall inside an exact collector-proven `using namespace std;` span. Any other token is a potential namespace/type/template-prefix owner. Any other or unproven `using namespace ...;` directive also blocks the whole std-template proposal, because the helper does not prove which competing prefix names it introduces. Invalid protection/import metadata supplies no exemption.

Protected directive spans require both exact original-source extent evidence and proven directive ownership. They preserve preprocessing roles: a source-written macro name inside `#define` is handled by the macro gate, not relabelled as a namespace declaration. Literal/header filename spans remain protected. Conditional/unknown/macro-affected namespace directives do not become accepted namespace spans. The helper does not choose branches, expand macros, change source bytes, or supply LOC units.

The proposed collector records an independent namespace-directive span as soon as an exact qualified header contract and directive scope/order are proven, before considering individual bare members. A source `struct vector` may block the bare member lookup without invalidating the independent `using namespace std;` syntax/namespace record. This keeps a clean qualified contract available for separate review. The macro token gate must still accept the actual directive's `std` token.

When any unsupported prefix/source-namespace form remains, the patch marks every returned qualified and bare std-template contract `namespace_prefix_review=True`; `_usable` refuses that flag. Exact diagnostic offsets, source text, and `source_wide_gate=True` remain in the result/environment. The gate applies even to uses before or outside the uncertain owner: no per-use scope certificate is claimed at this stage. Accepted directive evidence is retained separately as `std_template_namespace_directive_evidence`.

| Proposed fixture | Retained outcome |
| --- | --- |
| `namespace std=Custom; ... std::vector<int>*a,*b;` with `Custom::vector` a value template | Source-wide namespace-prefix review; no declaration promotion. |
| `using std=Custom;` or a source class/template owner named `std` | Exact source token gate; imported full-string contracts cannot bypass it. |
| Value/formal/function spelling `std` | Conservative potential-owner gate, without a semantic hiding claim. |
| Unknown `using namespace Custom;` | Source-wide competing-prefix provenance gate. |
| Conditional source owner or namespace import | No branch choice; retain whole-source review. |
| Exact proven `using namespace std;` plus a source class `vector` | Directive proof remains independent; bare `vector` conflicts stay gated while the qualified component is considered separately. |
| Comment/literal/header/directive metadata | Protected roles are excluded only with exact metadata; invalid metadata retains provenance review. |
| Explicit `::std::vector` | This first gate may recognize its `std::` token, but the existing type-prefix grammar still does not support the leading global qualifier; no new type proof is granted. |

The motivating bounded source slices use actual `std::` qualifications or exact `using namespace std;`. That observation is not a whole-pool certificate. A later scope-aware namespace/type/template-prefix collector can replace this source-wide gate only with exact owner order/lifetime evidence, alias target ownership, dependent/conditional/macro handling, and meaningful fixtures. The present gate, macro ownership proposal, and wrapped ordinary declaration gate must remain distinct dependencies in a future frozen reviewed stage. No chart/admission or normalized-count claim follows from these unexecuted artifacts.
