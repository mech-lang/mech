Proposed owner policy, requiring root's independent semantic approval:

- Import declarations and selected external annotations each own a semantic
  directive; an external function signature owns one declaration, its formals and
  types are structural. Bodyless functions without the actual selected external
  owner diagnose. Opaque generic types and custom constructor/typed-field groups
  expose declaration/field structure without treating types as executable work.
- Written fn/callback headers and closes are distinct from their body sequences.
  Every let/let assert consumes one actual pattern/initializer producer; tuple/list
  destructuring remains one binding. All independent expressions are preserved,
  including bodies nested inside arguments, record constructors and initializers.
- Case header/close, each written pattern/arm header, each actual body expression
  and nested arm-block sequence remain distinct. Pattern alternatives, formals,
  tuple/list items, labels, type parameters and operator operands are structural.
  Root approved combining the containing let/call prefix with its first directly
  nested case/fn header as one owner, matching qualified shared callback accounting.
  The AST still exposes the binding/pattern and every nested body for review.
  Distinct callbacks and preceding independent effects never merge. An earlier
  callable operand before a nested header diagnoses for source-bound semantic
  review rather than receiving a silent composition discount.
- Ordinary `{ expression }` arithmetic grouping must remain composed expression
  ownership, not a blanket executable/data brace rule. The AST records every
  grouping/body block and its actual statement sequence. The later canonical
  projection must prove scalar grouping and fold it into the outer expression;
  multi-statement let/effect/callback/control blocks keep their actual bodies and
  written closes. Unknown purity/ownership remains diagnostic/manual review.
- Actual utf8/bytes BitArray segments, tuple projections, lists/spread, custom
  record updates and pipelines have positive source fixtures. Unsupported segment
  modifiers, guards, use callback forms, arbitrary annotations or malformed
  lexical/owner syntax diagnose. Constant literal collections may be data; runtime
  calls and hidden callbacks cannot be waived as constants.
