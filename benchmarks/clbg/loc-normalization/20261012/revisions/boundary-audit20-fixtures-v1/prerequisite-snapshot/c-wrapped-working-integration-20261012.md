# Working wrapped declaration gate integration

The diagnostics-only helper is now called from the additive normalizer after
canonical events are consolidated and projected, and after effective contexts
are constructed. Its type source is the checked pre-event mask, not raw text.
It receives final event records and the actual logical preprocessing spans.
Accepted field, composed initializer and literal owners protect their exact
spans. No partial canonical header is relabelled as a full function profile.
Accepted ordinary alias events retain their complete statement boundaries;
aggregate bodies remain visible to independent field review.

Both wrapped type-prefix and displaced declarator-name checks retain review
diagnostics with no LOC units. Their output neither adds a counting event nor
changes the checked mask. The direct counter adapter, direct-declarator helper
and C++ value inventory remain unhooked proposals.

The final normalizer diagnostic list also preserves macro/type-use diagnostics
emitted by exact prefix probes after initial environment collection. Such
diagnostics previously could remain only in the local environment. This change
adds a review gate, not a numeric unit or a source mutation.

Twelve proposed integration methods exercise actual normalizer source
projection, inline parity, wrapped names and types, literal/data rows, aliases,
aggregate fields, for formals, callback bodies, macro diagnostic preservation
and an unaffected non-C language. These are unexecuted semantic assertions at
preparation time. All parser/import/test/hash work belongs to one frozen
common-mutex job; no source, timing, model, report or chart is admitted here.
