## Explicit external header contracts

The primary C++ working-draft synopses were read on 2026-10-12. They identify the exact namespace, class-template names, argument roles and defaults:

| Exact imported header | Header declaration | Bounded ownership contract |
| --- | --- | --- |
| `<vector>` | `template<class T, class Allocator = allocator<T>> class vector;` | [`[vector.syn]`](https://eel.is/c++draft/vector.syn): `std::vector` has two type parameters; one explicit argument is sufficient because the second has a header-owned default. The omitted allocator is structural contract evidence. This proposal does not infer an independently imported `std::allocator` template. |
| `<complex>` | `template<class T> class complex;` | [`[complex.syn]`](https://eel.is/c++draft/complex.syn): `std::complex` requires exactly one type argument. |
| `<array>` | `template<class T, size_t N> struct array;` | [`[array.syn]`](https://eel.is/c++draft/array.syn): `std::array` requires one type and one size value. This phase accepts only an exact unsuffixed decimal size literal, including zero; it does not infer a value's ownership from an identifier. |

No local libc++ installation path was assumed or searched. These are bounded language/header contracts, not a claim that the original compiler's physical header bytes were verified. Quoted/local headers, transitive includes and macro includes do not establish these contracts. The supplied semantic record must preserve the exact angle spelling and its original offset/length, and its masked span must belong to a complete translation-unit `#include` directive.

## Proposed API and proof boundary

`collect_std_template_contracts(cleaned, language, environment, *, resolver, semantic_imports=(), scope_ranges, conditional_regions=())` returns proposed `entries`, `evidence`, `diagnostics` and `proposal_only`. It never mutates the environment. The required resolver has signature `resolver(environment, name, absolute_offset)` and must return only a proven source/header type owner after order, lifetime, shadow and conditional checks. Supplied brace ranges must come from the same masked source. Known unclosed/unbalanced scope diagnostics gate this proposal.

Header entries use `explicit-header-class-template-contract`; unqualified names require a prior exact `using namespace std;` owner and use `explicit-standard-template-namespace-import`. The collector uses a private aliases overlay to resolve these namespace imports without changing the parent environment. Namespace imports have their enclosing scope lifetime and declaration order. At every unqualified use, the prefix helper also rechecks the qualified header owner with the supplied resolver. A `using` directive that precedes the direct header remains conservatively gated for names added later.

`prove_std_template_prefix(code, environment, offset, *, resolver)` returns `(end, exact_spelling, recursive_proof)` or `None`. It requires the exact absolute start of `code`; it never falls back to a global name guess. The recursive grammar starts only from an explicitly owned template, consumes exactly the contract's argument kinds and arity, and requires exact comma/closing-angle boundaries. Consecutive nested `>>` closers are consumed by their individual proven owners. Source type arguments use the supplied resolver at each argument's own token offset. Builtin type syntax, bounded cv qualifiers and type-argument pointer/reference tails are structural proof records; the outer pointer/reference syntax stays for the independent declarator resolver.

All proof records have zero units. The exact spelling and every source offset retain the input's wrapping and bytes; no source or mask is rewritten. This helper owns no formal, constructor argument group, initializer effect, independent name, executable statement, body/closer, literal/data wrapping or template-header binding. Nested template arguments cannot become extra declarations. The existing declaration/constructor mechanisms must supply those independent owners separately.

Unknown source aliases, source/dependent templates, template formals/packs, dependent members, arbitrary qualified member types, unknown external templates, malformed/unbalanced argument groups, wrong arity, unresolved argument ownership, conditional owners/shadows, macros, expired/shadowed names and all array size expressions remain gated. An expression's `<`, `<=`, `>`, `>>` or comma cannot establish a template owner. Recursion is explicitly bounded at 16 nested levels.
