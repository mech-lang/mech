# Future-suite grammar review: Nim, Crystal, and Pony

This additive static review inventories the current compact/optimized application paths for all ten workloads in each of Nim, Crystal, and Pony: **60 provisional source registrations**. The companion [JSON receipt](future-suite-grammar-review.json) enumerates every path and records the grammar and admission gates. The number of registrations is an inventory size, not a source LOC result. No source LOC, minimum, ratio, timing, source hash, or chart eligibility is assigned here.

These paths are mutable preparation inputs. Nim's additive private-v3 library-compatibility revision, Crystal's private-layout-v2 compiler-layout revision, and Pony's private-v3 metadata/reuse revision describe different preparation work; they are not source-normalization certificates. This review read source text, bounded syntax searches, and Pony compact/optimized textual differences. It did not import a parser or normalizer, lex or normalize a source, hash files, run tests/builds/probes, edit any application/manifest/report, operate on Git, or interrupt a timing process. Later locked verification must select and pin the exact qualified source revision.

## Common ownership rules

The common policy is one named function/control/type header, separate independent body statements and bindings, no extra unit for an executable opening delimiter, and one unit for each written executable closer. Layout dedents do not fabricate written closes. A declaration-section introducer is structural; its declarations still count. Data, argument/formal groups, tuple/destructuring producers, and loop headers require their own owners. Retain existing literal/data wrapping and meaningful compiler pragmas.

A proven value-only conditional or actual expression-only function/composition receives the reviewed expression treatment in its enclosing operand. This does not hide independent assignments, local bindings, transfers, or nested executable callbacks. Explicit callbacks retain header/body/written-close events even when they contain one expression. A type-field group differs from a constructor's data fields or function formals. Unknown ownership produces a review diagnostic and no admitted count.

Unknown interpolation/custom literal behavior, indentation continuation, pragma placement, and tuple-type/field ownership are explicit gates.

The ordinary `support/gmp_ops.nim` wrapper contains expression templates and is declared as general library support in preparation metadata. That exclusion must be verified against the qualified profile and library provenance; this review neither reclassifies it nor moves application work outside the count. The external wrapper's ABI/union repair is also a separate qualification gate.

Crystal must have its own lexical and ownership path; Ruby syntax resemblance is insufficient. Nested interpolation such as knucleotide's `"#{row[0]} #{"%.3f" % ...}"` requires accurate literal boundaries and an explicit interpolation-code gate until expression ownership is proved. Regex literals versus `/` division, `//` division, raw/percent/heredoc literals, annotations, FFI `lib/fun`, macros, setters (`def self.last=(x)`), postfix controls, and expression `case` branches need focused fixtures. No FFI declarations were identified in the current application paths; the standard-support file and external package dependencies still require separate provenance/exclusion review.

Pony masking needs `//`, nested `/* ... */`, regular/triple strings, characters, and apostrophe-bearing identifiers. Its type/method layout is not Crystal/Ruby's keyword scope. The current application paths do not contain explicit `{...}` lambdas or direct `use @ffi` declarations; future fixtures must cover these before accepting them. The declared ordinary GMP/regex packages require exact qualification and provenance. They do not authorize excluding application `Patterns`, `Substitutions`, `Worker`, parser, or coordination methods.

## Concrete implementation and fixture plan

Create three explicit families, not aliases: `foreign_nim.py`, `foreign_crystal.py`, and `foreign_pony.py`. Each exports `mask_<family>(source)` and `classify_scopes(cleaned, language, literal_spans=(), directives=())`, then a `binding_counter` and `normalize`. Masking returns offset-preserving cleaned text, literal/comment spans, retained directive evidence, and diagnostics. Ownership returns delimiter/layout/keyword contexts and event spans using the current `foreign_core` model. The normalizer returns evidence/proposal status; any unresolved gate means no admitted `normalized_loc` overlay. Benchmark names, inputs, helper names, and prior producer counts do not select grammar rules.

First qualify mask offsets/newlines, comment nesting, quote/character forms, operator contrasts, and meaningful pragmas. Next qualify paired packed/expanded examples for declaration sections versus actual types/fields, grouped names versus formals, tuple/destructuring producers versus chains, callbacks versus literals, headers/default arguments versus body assignments, and value-only versus imperative scopes. Finally qualify exact-source grammar under the mutex, retaining each source's diagnostics and independent role review. Pony recover and Crystal constructor-field shorthand stay pending explicit ownership decisions. Unknown pragmas, generated macro code, FFI bodies, layout continuations, interpolations, and following-call compositions stay gated.

The unhooked [foreign_future_mask.py](foreign_future_mask.py) and [test_foreign_future_mask.py](test_foreign_future_mask.py) now provide a bounded **unexecuted** Nim/Pony mask draft and 20 fixture methods. Only syntax compilation ran, without importing either module or running a test. The draft preserves character offsets and CR/LF positions; records comment/string/character/quoted-identifier spans; leaves Nim pragma syntax visible with pending semantic evidence; and retains Pony apostrophe identifiers, partial markers, receiver chains, capabilities, and recover syntax. It assigns no LOC. Crystal is explicitly unsupported by this draft; nested interpolation and regex ownership need its own pathway. No dispatch, normalizer, collector, candidate pool, or chart imports these files.

Before any display overlay, freeze the qualified revision and every application/helper/library boundary, verify exact source/profile/tool/dependency pins under `/tmp/mech-clbg-timing.lock`, run focused fixtures and source replay in an immutable one-shot job, and inspect its actual terminal receipt.
