# Clojure JVM comparison candidate

Source-only candidate. Nothing in this packet has been compiled, downloaded, executed, counted or measured. Root reviews the complete source/controller packet before one explicit metadata seal. The exact sealed digest is reviewed before preparation. All downloads, checksum/hash work, compiler invocations, fixtures, audits and native attempts acquire /tmp/mech-clbg-timing.lock; source editing and static review do not.

Twenty authored applications cover compact and optimized forms of all ten prescribed workloads. Application algorithms and control flow are Clojure. Standard Java BigInteger, Pattern/Matcher, ordinary arrays/maps/formatting/IO and thread primitives are used; there is no handwritten Java benchmark executor or external domain kernel. Every application includes the counted generic support/clbg/support.clj helper.

The selected language release is stable Clojure 1.12.6 (2026-09-02), with spec.alpha 0.5.238 and core.specs.alpha 0.4.74. Official sources are [Clojure downloads](https://clojure.org/releases/downloads), [release announcement](https://clojure.org/news/2026/09/02/clojure-1-12-6), and [Java compatibility/install guidance](https://clojure.org/guides/install_clojure). These recommend supported LTS Java 25. The existing MATLAB runtime proof is Temurin 25.0.4.1+1 ARM64 **JRE**, not a full JDK. This candidate selects the matching full ARM64 JDK from its exact official release so javap is available for compiled work review; it neither edits nor substitutes the existing MATLAB runtime.

Both forms compile to JVM bytecode before measurement. Each timing starts a fresh Java process with that immutable class tree plus exactly three pinned vendor jars; the runtime classpath contains no application .clj source roots. HotSpot performs its ordinary JIT inside the timed process. Planned execution category is JVM JIT, not native AOT. Compiler version, actual ARM64 runtime, selected G1 collector, classpath, flags, generated class bytes and actual authored compiler inputs remain pending until guarded receipts exist.

Planned JVM policy is -XX:ActiveProcessorCount=8, -Xms64m, -Xmx8g, -XX:+UseG1GC, with an eight-thread generic application pool maximum and 10GiB whole-group RSS bound. Compact forms run serial algorithms. Optimized tree, fannkuch, spectral, Mandelbrot and K forms partition independent complete work; regex runs nine tasks on an eight-thread pool, with the parent awaiting results. No dependent arithmetic phase overlaps its preceding phase.
