# APL preparation

The APL cohort uses GNU APL 2.0, built natively for Apple arm64 from the official GNU release. No usable installed APL/Dyalog runtime was found. Searches of primary repositories and the Benchmarks Game did not locate published APL versions of this complete suite, so these are newly authored APL ports of the canonical algorithms, not official submissions. Preserved cross-language algorithm references are in `upstream/apl/`; the exact source and runtime pins are in `apl-manifest.json`.

There are ten compact implementations and five additional array/IO optimized implementations. N-body, fannkuch, binarytrees, k-nucleotide and pi currently share their compact/optimized source. Their optimized manifest rows are timing aliases, with no extra measurements or claim that a faster alternative was found. Full timing selection is still required.

All application helpers are counted. The open-addressed integer-key counter in k-nucleotide is explicit APL and grows independently for all seven window widths. Its packed keys retain all bases of each window, with collision equality and linear probing. Frequency ties sort lexically. The sources preserve record boundaries, mixed case, CRLF normalization and FASTA comments in the sequence tests. The count assumes the selected THIRD record contains the benchmark DNA alphabet A/C/G/T.

N-body performs all ten interactions on every step and both energy calculations. Spectral norm computes every coefficient on every multiply; the optimized version merely groups 64 output rows. Mandelbrot computes actual recurrence/escape tests for each pixel, handles odd widths with zero tail bits and writes the complete PBM. The optimized version groups 16 rows. FASTA performs every LCG update and compares unscaled binary64 random values to cumulative binary64 probabilities, with `⎕CT←0` to disable APL's approximate comparisons; the optimized version batches 60,000 successive draws and complete line output. Both regex forms construct actual successive replacement strings. Binarytrees allocates a fresh nested array per node, calls both child builders separately, releases the stretch root and retains the long-lived tree during temporary construction.

GNU APL has no arbitrary-precision integer cell. Pi uses a general GMP binding through GNU APL's documented native `⎕FX` interface. The binding exposes only allocation/lifetime, scalar set/copy, ordinary arithmetic, comparison and checked scalar extraction. It contains no spigot state, pi extract, iteration or formatting. APL evaluates both exact extracts before every attempt and performs every consume/produce transition. This support is analogous to the general GMP library support used for other languages. Its source, binary and GMP library are pinned. Interface/license provenance is recorded in `support/apl/`.

GNU APL unconditionally writes a session newline to stdout on `)OFF`. The general `run-apl.sh` launcher preserves fd 3 as application stdout and routes interpreter/session messages to stderr. APL opens that descriptor and performs every output operation itself; the launcher does not change bytes, inspect benchmark inputs or run any computation. Startup and launcher overhead stay inside measurement.

`prepare-apl-runtime.sh` fetches the pinned source and rebuilds the local interpreter plus general GMP binding. Runtime/build artifacts are under `.build/toolchains` and `.build/apl-support`, outside candidate source. `validate_apl.py` runs canonical small and adversarial checks while holding `/tmp/mech-clbg-timing.lock`. No full workloads were timed during preparation. In particular, plain interpreter loops make the full n-body, fannkuch, binarytrees and seven-map k-nucleotide workloads likely timeout candidates; a timeout must remain unmeasured, without extrapolated chart numbers.

Primary runtime documentation: https://www.gnu.org/software/apl/ and https://www.gnu.org/software/apl/apl.html. GMP arithmetic: https://gmplib.org/manual/Integer-Arithmetic. GNU APL source archive: https://ftp.gnu.org/gnu/apl/apl-2.0.tar.gz.
