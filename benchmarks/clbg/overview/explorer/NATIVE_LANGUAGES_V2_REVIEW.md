## Prolog interpretation and QLF closure

Actual metadata execution must be `Interpreted`; the verified backend template
uses `native-interpreter` / `interpreted`. This identifies the native runtime
platform and actual interpreted application execution separately. Metadata
requires scored native architecture `arm64` and literal `emulation_used:false`.
`interpreted_vm_evidence` is an actual reviewed object, not a name default:

```text
status: qualified-actual-interpreted-native-vm
interpreted_vm_execution_verified: true
native_aot_proven: false
native_machine_code_jit_proven: false
runtime_binary / runtime_binary_sha256: exact scored command[0] and pin
profile_ids: all20 exact original scored IDs
review: passed + review_identity + evidence_path/evidence_sha256 in meta pins
```

Every original Prolog profile's authoritative input inventory additionally
needs `runtime_artifacts` and `runtime_receipt`. Artifacts are a nonempty unique
list `{path, sha256, kind:swi-qlf-bytecode}` equal to the retained scored row's
list and pinned by both canonical inputs and actual metadata. The passed
runtime receipt `{path,sha256}` binds original load/QLF/WAM/runtime/source bytes
and is pinned by both. The importer checks every QLF byte hash before staging
and retains these artifact identities on the published program. Independent
original runtime/VM semantics and actual graph work must pass before flags true.

For both new interpreted languages, every runtime/load receipt additionally
contains `binding_field` (an actual JSON pointer) and `binding`, the exact
original profile ID, complete scored argv, executable SHA, main source path/
SHA, complete authored input path/SHA list and selected runtime-artifact list,
plus literal true `source_loading_verified` and `startup_input_closure_verified`.
The importer reads the pinned receipt bytes and requires that actual field to
equal the declared binding before staging; no expected-path-presence heuristic
replaces actual launch/load identity. It retains original `source_path`,
`runtime_input_bundle` and `runtime_load_evidence` on the admitted program. The
platform stage rechecks these against full scored argv, executable and counted
source hashes, and its guarded entry rereads the actual receipt field before
commit. Wrong final QLF/source argv, omitted loaded helpers, changed actual
binding bytes and numeric1 substituted for positive flags reject. Canonical
source display order and original compiler/load inventory order need not match;
complete original path identities and SHA multiplicities remain bound.

SWI [QLF](https://www.swi-prolog.org/pldoc/man?section=qlf) describes portable VM
instructions; [ABI versions](https://www.swi-prolog.org/pldoc/man?section=abi-versions)
bind the VM/format. [Clause indexing](https://www.swi-prolog.org/pldoc/man?section=jitindex)
does not establish application native-code JIT. Packaging/QLF compilation or
the native runtime executable cannot establish application native AOT.

## Rebol original load and native runtime closure

Rebol metadata requires the same positively interpreted status/false AOT/JIT
flags, exact native ARM64/nonemulated runtime image and verified backend tuple.
`execution_model_review` must be passed with pinned identity/evidence, execution
`Interpreted` and exactly all20 scored original profile IDs. For every profile,
scored command[0]/binary SHA must equal the reviewed interpreter image and its
metadata pin; canonical input inventory must include a passed original source/
glue/runtime load receipt pinned by both count evidence and metadata. This
requires complete original Rebol plus authored extension/loader/ABI source
bundles, never only a main script. General GMP/PCRE2/IO extensions must appear
in actual source/runtime/library evidence before admission.

The [tagged Oldes/Rebol3 README](https://raw.githubusercontent.com/Oldes/Rebol3/3.22.1/README.md)
identifies the selected interpreter family. The
[tagged datatype help](https://raw.githubusercontent.com/Oldes/Rebol3/3.22.1/src/boot/typespec.reb)
describes user functions as interpreted. These are documentary definitions,
not actual runtime qualification/version/build/architecture receipts. The
source-only research and capability notes at rebol-comparison/20261013 require
a later private publisher-verified native bootstrap and counted general glue.
No runtime was executed by this adapter proposal.

## Platform and language groups

The platform stage binds the exact actual JSON-pointer runtime value and saved
report hash, actual compiler/native architecture/memory true flags, all20
original measured commands/source bundles/reports and all relevant runtime
image/QLF pins. The importer must precede platform annotation; grouping must
follow it before endpoint pruning. Both new languages require interpreted
backend evidence. Group stage checks all20 verified records per language and
adds Prolog/Rebol to Interpreted and Dynamic; no Array/Functional membership is
inferred. Native GC membership comes only from actual memory strategy receipts.

Prolog dynamic/logic facts use SWI
[C++ interface](https://www.swi-prolog.org/pldoc/man?section=cpp2-intro) and
[single-sided unification](https://www.swi-prolog.org/pldoc/man?section=ssu).
Rebol dynamic typing is based on the original
[word/value semantics](https://www.rebol.com/docs/core23/rebolcore-4.html) plus
the selected [tagged runtime evaluator](https://raw.githubusercontent.com/Oldes/Rebol3/3.22.1/src/core/c-do.c)
assigning evaluated values to words. This does not confer an execution class.

The native record/suite reconciler also needs a separately reviewed additive
eight-language route. The new cohorts are dated20261013, unlike the frozen
six20261012 paths. This packet invents no90-record output, metadata qualifier,
runtime version, source count, ABI, release-year receipt or future digest.
