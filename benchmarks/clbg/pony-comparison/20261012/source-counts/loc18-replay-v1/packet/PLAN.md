# Pony exact compiler input / canonical LOC candidate

Source-only authoring. No hash, parser, fixture, audit, normalization, compiler,
native process or queue has run. Frozen production evidence, timings, proposals,
private-v7 and work revisions remain unchanged. This proposal lives in its own
new revision and creates only additive output after separate root packet review.

The twenty final profiles come from successful private-v7 production/primitives
qualification. Its exact prior-proof-reuse receipt binds the original source,
binary, original command and original build receipt across private-v1/v3/v4/v6.
The inventory never labels all twenty binaries as compiled by the private-v6
compiler merely because that is the final qualification toolchain. Preserve each
actual retained build command/compiler/source snapshot and every original pin.

input_inventory.py reads original build stdout/stderr Building records, then
enumerates every direct nonhidden .pony file of each actual loaded authored
package. It also inventories native .c inputs and stops their LOC qualification
pending their own grammar. The exact tagged [Pony package loader](https://github.com/ponylang/ponyc/blob/95ad18015d04f4414d0fd4f469ed6b2e9b9b9e73/src/libponyc/pkg/package.c)
uses direct directory entries and sorted source-file order. Nested package
directories require separate actual package records. Unknown package paths or
unbound source bytes stop rather than receiving a vendor/single-file waiver.

Observed examples from retained raw build stderr: Pi loads the authored
source-snapshot/support-v2/ponytest alias package; K does not load that package
although its search path is available. All files in a loaded authored package
count, including aliases/glue unused by reachability. Search-path presence by
itself neither includes a package nor permits dropping a loaded helper. Compiler
standard packages and the exact pinned vendor regex/GMP packages are separately
inventoried and excluded under the agreed generic-library boundary.

Canonical replay uses the actual qualified LOC18 snapshot/672-test receipt and
its exact frozen module/Pygments2.19.2 dependencies. Preserve every full per-file
metric/expansion/diagnostic and count the actual main first plus all authored
helper files once per profile. Producer LOC stays unchanged, including null;
no producer number or physical count substitutes for canonical units.

Pony aliases currently produce dedicated type-alias diagnostics in the bounded
LOC18 grammar. Other selected-source diagnostics remain explicit too. Separate
source-specific manual ownership review must bind actual replay/source hashes,
exact existing owner events and every diagnostic/span. It can approve the
existing owners or demand an additive grammar fix/replay; this candidate cannot
override a count or supply a blanket language waiver. Source-role completeness
review separately binds the independent original compiler/package inventory.

overlay_candidate.py validates the complete twenty-source cohort before any
qualified evidence is written. The separately retained compiler inventory is
authoritative; an overlay bundle does not certify its own completeness. Later
qualified input evidence and exact-source LOC overlay follow the root contract
in continuation/qualified-loc-overlay-format-v1.md, preserving all raw proposal
diagnostics and original timing/source bytes. Charts/publication remain outside
this packet. Actual locked receipts and root semantic review are prerequisites,
not schema flags masquerading as evidence.
