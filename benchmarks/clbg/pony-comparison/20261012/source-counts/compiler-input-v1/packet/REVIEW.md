# Source-only inventory/replay/overlay packet

Files: input_inventory.py, overlay_candidate.py, test_loc_inputs.py,
qualify_loc.py, PLAN.md and this review. All are authored and unexecuted. Root
must review/freeze the exact packet before a command is considered for the shared
mutex. No private-v7/work source or frozen qualification evidence is modified.

The inventory stage requires actual successful private-v7 report path/digest;
it cannot start from a future proposal or stopped private-v6 report. It binds
the private-v7 prior-proof-reuse receipt and each retained original build receipt,
both raw compiler streams, actual compiler bytes, link target and source/binary
identity. Whole authored package file lists are independent of the LOC bundle.
Unknown package roles/unpinned extra files stop; native authored shims retain an
explicit unresolved grammar gate. Standard/generic vendor inputs are still listed
and pinned. Original compiler provenance across four revisions remains explicit.

Eight exact synthetic fixture methods cover both log streams/duplicates, entire
helper packages, available-but-unloaded package exclusion, unpinned extra files,
unknown packages, command/binary/mutex failures, diagnostic/count override refusal
and incomplete cohort/integer gates. They start no compiler/native child. Actual
discovery/start IDs and zero skips/expected failures/unexpected successes are
required, with exclusive raw log and receipt plus terminal pins even on failure.
Only the initial inventory stage runs these eight new fixture methods. Later
stages verify and reuse their exact saved receipt and unchanged packet pins;
successful fixtures are not repeated merely to advance the pipeline.
Exact Python executable and unittest package .py source pins precede their locked
import/use, with fresh-cache and loaded-module path checks and post-import pin
reconciliation. Original compiler layout is asserted per each of the twenty
actual retained receipts, matching its source snapshot and build origin; cleanup
errors/live remaining groups invalidate the retained compilation evidence.

Replay copies the actual qualified LOC18 dependency bytes to a fresh read-only
snapshot before import, verifies actual module locations and reconciles pins;
Pygments2.19.2 init identity/version and package source pins are retained. All
normalization/hashes occur after actual common mutex acquisition. The unchanged
LOC18 672-test receipt is reused, not relabeled as a new fixture run. Actual
per-file raw metrics, source lengths, expansions, owner events and diagnostics
are preserved. Only separate exact-source semantic review can admit counts.

The review file supplied for overlay must bind the raw inventory and replay
digests. Per profile it records the complete actual package/classification list,
source/binary/compile identity and authored files. Per file it records the exact
source hash/character length, physical/canonical proposals, entire actual owner
event/expansion inventories and explicit dispositions for each diagnostic/span.
Every cited disposition owner must exist in the actual count receipt; count
overrides and missing/unresolved dispositions stop. A needed grammar repair gets
an additive revision/fixture/replay, never a rewritten saved number.

Only after all twenty rows pass does the overlay stage create separate qualified
compiler-bound inventory evidence and the root-contract LOC overlay. Chart
admission stays false and timing/source/report bytes remain preserved. Root must
confirm terminal pins and the complete cohort before the importer uses it.
