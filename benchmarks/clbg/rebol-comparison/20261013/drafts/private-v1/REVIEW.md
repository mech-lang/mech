# Rebol3 baseline source proposal

This packet is authored source only. Nothing here has been imported, parsed,
hashed, built, installed or run. No primitive, output, work, allocation, runtime,
source count or timing evidence is qualified. Root owns any later operation
under the existing common timing mutex and an exclusive durable owner lease.

The selected candidate is Oldes/Rebol3 3.22.1 Bulk for native macOS ARM64,
executing authored Rebol in its native interpreter. The publisher gzip SHA in
the parent RESEARCH_PLAN.md is a discovery fact; there is no locally verified
runtime or native extension in this proposal. Red is outside the current goal.

The first packet has one baseline per workload. It proposes two publication
forms as explicit equivalent-source aliases later, after the baseline source
bundles are frozen. No distinct optimization or sibling timing reuse is claimed.
All source, loader and authored native facade code belongs to the complete
counted application bundle for each using program; vendor libraries are
separately disclosed and pinned. There are no source counts in this packet.

The source programs use a counted byte IO/formatting helper and the proposed
general native extension. Its ordinary POSIX chunk reader reserves a managed
result before consuming input, uses stack bytes and handles EINTR/short reads;
the counted Rebol IO facade collects chunks until EOF. Its write loop emits
every byte and handles EINTR/short writes. Rebol splits records with CR, LF and
CRLF handling, assembles all output and calls the generic write once. The tagged
file actor can consume a pipe while measuring `/dev/stdin`; neither that path
nor console LF/ESC handling is used. These source facts still require actual
runtime/ABI/byte and failure fixtures before even bounded benchmark execution.
The argument block and formatting operations also require actual primitives.
Formatting uses a counted general C `%.*f` command on the original double;
LC_ALL=C, default FPU rounding, halfway0.0625/3,2.675/2,negative and full9-digit
fixtures are required. No scaled decimal-rounding approximation remains.
The default collector stays enabled; no recycle suppression or manual collection tuning is
proposed. No optional native JIT is selected.

The tagged 3.22 source distinguishes integer division `//` from remainder `%`
and modulo `%%`. The authored integer divisions use `//`; ordinary `/` is used
where decimal division is required. Signed64-bit integers can hold all18-base
K encodings. They cannot hold the unbounded Pi state.

Review these concrete source properties before a runtime preparation packet:

1. Binarytrees constructs a new two-slot block before every depth branch,
   including every leaf; it recursively creates both children and traverses
   them for checks. A live named long-root reference survives every churn loop
   and is checked afterwards. Original interpreter allocation/lowering, actual
   same? series identities, graph lifetime and normal-GC retention still need
   actual receipts. No arithmetic tree-check substitute is present.
2. K allocates seven initially empty native maps and inserts every complete
   window for widths1,2,3,4,6,12,18. It decodes keys, ranks full frequency maps
   and performs the five query lookups only after all map work. Actual native
   map growth/capacity, complete map totals, key equality and iteration semantics
   remain mandatory primitive/work evidence. The input selection ignores
   preheader data/comments, selects the exact THREE token and stops at the next
   record. No query-only table or fixed preallocated DNA index is used.
3. FASTA builds floating CDFs, updates the naive LCG for every generated byte,
   uses the floating draw against cumulative probabilities, carries the TWO
   seed into THREE, and wraps actual output at60 columns. No RNG cache or
   precomputed integer cutoff appears.
4. Revcomp retains headers, discards preheader text and semicolon comments,
   traverses each complete sequence in reverse, applies the ambiguity/lowercase
   complement table and wraps at60 columns. Binary parsing and all output bytes
   require independent preheader, CRLF, boundary and ambiguity fixtures.
5. Fannkuch uses factoradic prefix rotations, copies the working permutation
   anew for each rank, flips until its leading zero, applies rank parity and
   records checksum/maximum over all n! permutations.
6. Spectral performs all40 dense products with separate coefficient, ordinary
   and transposed product functions, then complete final dot products. Nbody
   performs all ten pair forces, both velocity contributions, all five position
   updates for every requested step and both energy reductions in strict
   ordinary decimals. Mandelbrot performs every pixel with its50-step
   recurrence, packs eight-bit rows and pads the final PBM byte.

All ten main bodies and the five support sources are authored. Pi explicitly
constructs both unbounded numerators, performs both actual floor divisions and carries Q/R/T/K state in
Rebol. Regex explicitly scans every variant and assembles each sequential
substitution in Rebol. These two mains use the proposed general facade contract
in PRIMITIVE_CONTRACT.md. The C implementation uses the exact tagged sample's
entry signatures and full generated SDK macros; no partial RL_LIB layout or
numeric type-code substitute is authored. Actual SDK generation, complete SDK
dependency pins, compilation and extension loading are outstanding. The native
module also contains generic raw IO, so every profile counts the whole authored
C source/loader and discloses both linked vendor libraries, even where only IO
is used. No REBOL2 routine! API, public bigint datatype or installed library
export is assumed. The facade performs ordinary GMP signed arithmetic, PCRE2
finding, raw byte IO and fixed decimal formatting. All Pi state,
both numerator divisions, regex counting and sequential substitution assembly
belong in Rebol source.
Native primitive implementations may not contain workload-specific constants,
loops or orchestration. Handle-free call-local native temporaries are preferred;
all library, allocator, binary-series and failure ownership still need review.

The C boundary deliberately caps byte series at INT32_MAX-64, below the tagged
MAX_I32 allocator bound with terminator/alignment room. The VM OOM path is a
nonlocal trap, not a NULL result. Arithmetic reserves a bounded result before
acquiring native buffers/GMP values and reacquires input views afterwards; its
fill cannot expand past that reserve. IO/formatting carry only stack storage
across VM allocation; PCRE2 releases resources before the VM allocates the
returned pair. Actual vendor fatal-OOM/process cleanup and VM trap behavior
remain required failed-outcome evidence; no all-path recovered execution is
claimed. No allocator, collector or trap policy is changed.

Before any bounded source run, root must review an additive private bootstrap
with exact release/source pins, original ARM64 runtime image closure, actual
version, ordinary GC configuration, explicit noninteractive arguments and
child-local security/module policy. The tagged startup loads adjacent boot
rebol.reb, data/user.reb and user-module locations. That bootstrap must create an
exclusive private runtime directory/REBOL_HOME with those bytes absent or
pinned, without changing global HOME. The extension is selected only through
an explicit root-pinned absolute child-local MECH_CLBG_REBOL_PRIMITIVES path;
the loader installs/downloads nothing. Then qualify the generic library and byte
operations, complete source/library inventory and independent bounded outputs.
Required tree/map/Pi work witnesses, exact original source-owner grammar/replay,
unchanged Mech controls and full fresh-process timings follow separately.
Every failed attempt retains its original bytes and identity; none is retried,
replaced, relabelled or promoted by this source proposal.
