# Required-work audit

Correct output alone does not qualify an implementation. This audit checks
the Mech source algorithm, emitted computation, and general runtime pathways
against each Benchmarks Game description. It does not represent an official
Benchmarks Game acceptance decision.

Two Mech comparison issues were corrected:

| Benchmark | Issue | Current strict profile |
|---|---|---|
| Spectral norm | The 9-LOC rewrite omitted the four required source functions. | Four functions, 12 LOC, median 0.088515 s, sample SD 0.003140 s. |
| FASTA, compact | General compiler optimization converted floating comparisons into integer cutoffs. | Transform disabled; 32 LOC, median 1.227297 s, sample SD 0.005143 s. |
| FASTA, expanded | Same compiler transformation. | Transform disabled; 43 LOC, median 0.573188 s, sample SD 0.002935 s. |

Each corrected endpoint has five fresh-process samples at the full standard
input. Complete output hashes match the references. FASTA disassembly retains
floating division and comparisons; its random sequence is generated by
200,000,000 fresh LCG updates. Repetition caching applies only to the supplied
fixed ALU string.

K-nucleotide performs all 874,999,961 library hash-table window updates across
the seven required lengths. Its general runtime verifies each histogram's
total. The independent five-run confirmation measured Mech at 0.509095 s and
Rust #7 at 0.540322 s. The BQN and K implementations investigated here instead
use indexed pair counts and selective long-string searches; they are excluded
from the strict comparison. Their compact spectral-norm sources also omit the
four functions and require faithful replacements.

Binary trees constructs and walks all 613,766,494 ordinary nodes at the full
workload. Leaves have the same allocation as interior nodes. The source uses
Mech's general core library memory pool, which is disclosed as the allocation
strategy. The generic allocator does not implement a binary-tree algorithm.
Pidigits retains both extract(3) and extract(4) for every tested candidate; its
advance variant uses the same impossible-candidate guard as pinned Rust #4.

The compiler correction supports transitive scalar helper calls inside matrix
comprehensions. It follows function bodies and rejects impurity and recursion;
it does not identify benchmark names or inputs. All 51 native-sequence tests
pass. Rebuilding 13 unchanged Mech programs produced identical native compute
objects. The untouched n-body reactive backend retains its previous full-state
validation.

`audit.json` records evidence and required work for all ten Mech benchmarks.
`builds.json` pins compiler, source, binary, build environment and native objects.
`timings.json` preserves the corrected and historical control samples. Build
and timing phases are separate:

```
python3 benchmarks/clbg/work-audit/20261009/run.py build
python3 benchmarks/clbg/work-audit/20261009/run.py measure --samples 5
```
