# Exact source adapter proposal

source_adapters_candidate.py is an unexecuted pure text editor for the seventeen
read original files. It has no CLI, file read/write, hash, process or compilation
path. Only a later reviewed mutex-held generator may call it, after reconciling
each original source/report pin in existing-source-roles.json. Unknown/changed
anchors stop instead of guessing a Julia source boundary.

Each proposed edit retains its original character offsets, literal original and
replacement text, and purpose. Driver removal uses the entire reviewed terminal
suffix. Original algorithm definitions stay exact apart from the explicit regex
literal-to-runtime-constructor replacement. All remaining original bytes must be
reconciled during the locked generation; original files and JIT reports remain
unchanged. There are twenty roles and seventeen unique source implementations,
so the shared nbody, spectralnorm and FASTA role sources must not be silently
replaced by different optimized algorithms.

The proposed compiled source has uninitialized typed state declarations, an
initialize_runtime_state function, and a run_original_driver function. It does
not call either function at image build/import. entry_template.jl calls them in
that order after receiving fresh runtime arguments. All actual compiled derived
Julia text, entry glue and C driver count once in the later LOC bundle. Original
provenance copies are evidence, not an extra counted compiled file.

Nbody constructs the exact four bodies and original sun at runtime. FASTA resets
its Ref seed and constructs both original probability vectors, preserving the
read-only CodeUnits literals. Revcomp binds real runtime streams and repeats the
exact table fill. Pi4 assigns the original global n for trailing-line labels.
Regex initializes original vector/tuple shapes with fresh Regex objects, including
the input-cleaning Regex inside the body; the original patterns/default flags and
PCRE.exec override remain explicit. Ordinary vendor regex compilation/JIT is
allowed and disclosed. The other working arrays/maps/BigInts remain inside their
original runtime functions.

Const-to-typed globals and abstract IO types are explicit source/performance
changes. Every selected derived implementation needs fresh matched JIT measures
alongside its AOT measures; original JIT records remain available separately.
Even driver-only changes need exact matched-source provenance. No source adapter
can qualify immutable Julia tree allocation, native method coverage, serialized
state or distributed runtime behavior. Those remain actual evidence gates.
Tree construction remains unchanged until scored compiler evidence decides
whether fresh-leaf repair is needed. Such a repair would create another revision
and another matched JIT comparison, preserving this candidate and old records.

The binarytrees4 source has a concrete unresolved module-context issue:
[@everywhere executes in Main](https://docs.julialang.org/en/v1/stdlib/Distributed/#Distributed.@everywhere),
even when written inside another module. Its Node/make/check definitions cannot
be assumed to belong to a future containing package such as ClbgApp. The original
binary_trees function was also in Main, but a generic package wrapper would move
that function while its referenced definitions remain elsewhere. Stop that
module-context generation until a separate exact definition placement/binding
adaptation is reviewed. Julia1.13.1 selects Distributed.jl commit
661112ef29b8d371b8612b94a629c0bbcf3d36f7 via its stdlib/Distributed.version file;
later pin and inspect that exact macro expansion. No timed eval or extra workers
can resolve the gap, and no generic wrapper is qualified by this text editor.

The matched JIT process must load these same derived workload/state functions
using the original ordinary Julia compiler policy, with loading/compilation
inside its timed process. A compile=yes invocation of the already fully compiled
AOT library does not establish a JIT counterpart. Execution-specific generic
entry/launcher glue is explicitly inventoried and counted; its runtime cost
remains in the respective whole-program measurement. A mode-specific loader may
not alter the initializer, worker policy, algorithm functions or runtime input.

Before any generator/compile/probe queue, review these exact edits together with
direct_driver.c, entry_template.jl, RUNTIME_STATE_STRATEGY.md, AOT_PROOF_PLAN.md,
negative_canary.jl and proof_candidate.py. The final observer must reject Julia
JIT/interpreter activity even when a missing-native-method canary exits zero and
trace-compile is empty. Source generation, fixture proofs, hashes, compilation,
native observation and timings all require the actual shared common mutex.
No command was executed and no Julia artifact is qualified by this packet.
