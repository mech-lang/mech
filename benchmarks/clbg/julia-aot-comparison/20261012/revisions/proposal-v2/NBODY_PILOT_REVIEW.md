The build-only pilot uses the actual existing nbody-julia-5 source shared by both
selected Julia roles. It verifies that source and its immutable original timing
report before calling a fresh pinned copy of the reviewed source editor under
the common mutex. The exact original numerical bodies remain unchanged. Only
the original mutable body initialization and terminal driver move into runtime
functions, with typed uninitialized global state. Every edited/untouched source
span, counted Julia/C input and separate matched-JIT loader is recorded.

The exact completed Julia1.13.1/PackageCompiler2.4.3 bootstrap and original cache
pins remain immutable. A new copied depot owns new compiler/cache writes. The
precompile script requests only method/type compilation and asserts bodies are
unassigned before and afterward; it never runs the initializer, workload, entry
or matched JIT. This does not prove the final image's restored state or native
method coverage: those still require actual separate observation.

The create_library call retains the previously successful canary recipe and
requests an additional LLVM bitcode candidate. The exact installed2.4.3 producer
passes sysimage_build_args into its fresh base and final app image builds, so
intermediate build writes may reuse this path; only the bytes after the complete
final build are pinned. The bitcode remains a candidate until its final module,
scoped app definitions and emitted native code are independently reconciled.
The official Julia command-line reference documents --output-bc:
https://docs.julialang.org/en/v1/manual/command-line-interface/

The same original C launcher links the new library. Native architecture and
actual resolved dependent images are recorded without running a workload. All
build/link/image/hash actions and inherited child cleanup retain the one mutex.
Exclusive output/build directories and immutable snapshots prevent overwriting
the canary, original sources, old JIT samples or other completed proof attempts.
Partial build/receipt/error bytes are retained on failure. The script performs
zero benchmark or canary executions and cannot admit an AOT measurement.

After source review, the proposed single build-only command is:
python3.14 -B benchmarks/clbg/julia-aot-comparison/20261012/build_nbody_pilot_v1.py

Runtime pilot qualification, final-state inspection, calibrated interpreter/JIT
observation and native/invoke coverage remain mandatory. Fresh matched derived
JIT and AOT complete-process measurements use identical workload/state bodies.
All ten workloads and twenty original roles still remain the complete goal.
