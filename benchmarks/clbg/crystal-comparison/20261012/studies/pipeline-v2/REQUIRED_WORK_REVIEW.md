# Crystal complete application work review

This review covers the two current application forms for each workload. The
full-study sealer binds it to the exact qualified source hashes, complete
bounded output records, ordinary primitive proof, and required actual work
traces. It supplies no elapsed-time or source-size claims. Native qualification
and an independently reviewed full manifest remain prerequisites to execution.

Both nbody forms initialize five bodies, offset solar momentum, print energy
before and after all requested steps, and process the triangular ten body pairs
using ordinary exact square root and division. Compact updates positions after
the pair loop. Optimized updates a body's position after its last interaction;
later pairs no longer use that body's old position. Neither caches forces or
uses a reciprocal approximation.

Mandelbrot compact evaluates each requested pixel with at most fifty real
recurrences and an escape check each iteration. Optimized evaluates eight lanes
with escape reductions after each five actual iterations; only valid lanes
affect its early exit or final byte. It launches at most eight contiguous row
jobs, joins them, sorts by starting row, and writes all requested PBM rows.
Trailing invalid bits remain zero, and zero dimensions produce only the header.
The bounded exact-output inventory includes odd sizes and byte boundaries.

Both spectral forms perform ten iterations of two A-transpose-A applications,
therefore forty fresh implicit products. Compact computes the prescribed
coefficient from row and column on every inner iteration. Optimized derives its
integer denominator from the same expression and advances it by the triangular
denominator differences for each successive column, using four accumulation
chains and a scalar tail. Every input coefficient is divided on every product;
there is no matrix or coefficient cache. At most eight disjoint row jobs join
before a result vector is consumed, and the final dot products visit all rows.

Both binarytrees forms use class Node objects, independently call the recursive
creator for both children, and allocate each leaf with Node.new. A helper limits
the stretch root's lifetime; the real long-lived root remains referenced until
its final check. Every temporary iteration constructs and traverses a fresh
tree. Optimized dispatches batches of at most eight independent depth jobs and
joins before printing ordered results. The required trace copies observe every
actual constructor, child edge, root, and long-lived identity, while retaining
audit references solely to prevent allocator-address reuse in the audit copy.

Compact fannkuch enumerates the standard mixed-radix permutation sequence and
performs actual prefix swaps on a fresh permutation copy. Optimized initializes
each rank interval by descending-width factoradic rotations, partitions all n!
ranks without overflow, and advances through every rank in each interval. It
uses the global rank parity for checksum, performs actual prefix reversals, and
reduces all worker maxima and checksums after joins. Up to eight intervals cover
all ranks, including awkward tails; all permutations through n8 are bounded
output checks. Neither form caches flips or permutations.

FASTA forms emit the prescribed repeat and random records with 60-column lines.
Compact carries an exactly representable binary64 LCG state; optimized carries
an integer LCG state. Every requested random letter advances that state and
performs direct binary64 division by139968. Both accumulate ordered unscaled
binary64 CDFs. Optimized uses a per-draw binary search and bounded output buffer;
it does not replay periods or cache random letters. Repeat-record literal
replication is distinct from the random draws. Boundary checks cover zero and
partial lines, repeat wraparound, carried record seed, and complete n20000 output.

Both knucleotide forms select only the exact THREE token, tolerate the declared
comments, line endings, and case, and stop at the next record. They construct
ordinary growable maps for all widths1,2,3,4,6,12,18, including every overlapping
window for the first two frequency maps and the five query maps. Optimized packs
each window into a rolling UInt64 key in seven independent jobs, joins all seven,
and decodes only for ordered formatting. Actual map-trace reconciliation covers
every real key, count, size, and total for both forms on the full bounded input
inventory. Query-only counting and precomputed frequency tables are absent.

Both revcomp forms preserve every header and record, handle CRLF/CR/LF, comments,
and EOF, and complement all prescribed upper/lowercase IUPAC symbols to uppercase.
Compact uses general String reverse/translate and complete wrapped writes.
Optimized parses ordinary bytes, swaps and complements both ends in place, and
uses bounded writes. It consumes all record bases and emits all output bases.

Both regexredux forms use ordinary PCRE2-backed Regex operations for all nine
nonoverlapping pattern counts, retaining each complete count. Optimized creates
private Regex state in eight count jobs, joins those jobs, and evaluates the
ninth count. Both then perform all five prescribed substitutions sequentially,
in the specified order, and print complete original/cleaned/final lengths.
Bounded counterexamples distinguish ordered substitutions and zero/multiple
nonoverlapping matches. No benchmark-specific host helper supplies counts.

Both pidigits forms use general immutable BigInt operations and two independently
executed integer quotient extractions for every tested candidate. Compact forms
3q+r and4q+r before the two divisions; optimized carries those distinct endpoint
numerators directly and divides each by its denominator. Acceptance, state
updates, ten-digit padding, tails, and printed counts remain application code.
Actual trace reconciliation records and independently verifies both full
numerators, divisor, quotients, acceptance decisions, and complete stdout at97
digits and zero. The generic primitive proof checks floor/truncated division
semantics and operand lifetime through garbage collection.

All language forms use ordinary standard library/runtime operations. Compiler
release optimization and native CPU selection remain identical across forms;
no fast-math or disabled-GC option is introduced. Application scheduler capacity
is explicitly capped at eight where parallel jobs are used. No source-size
normalizer success is inferred from this work review.
