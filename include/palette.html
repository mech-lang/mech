Expanded code syntax palette

The background layer stays quiet: operators, brackets, and ordinary identifiers are pale purple; literals are blue; kinds are pink. Functions are green, matches are sand-yellow, and state-machine structure uses orchid and periwinkle. Delimiters stay inside their construct family but step darker: purple tuple parentheses, green function parentheses, rose kind brackets, and yellow atom/state colons and parentheses. Atom names remain the exact same yellow everywhere. Bold weight, indentation, and rails still carry the hierarchy when color is removed.

bubble-sort.mec4 states / long-form scan test
#bubble-sort(arr<[u64]>) ⇒ <[u64]> :=
  ├ :Pass(arr<[u64]>, acc<[u64]>, swaps<u64>)
  ├ :Next(arr<[u64]>, swaps<u64>)
  ├ :Reverse(arr<[u64]>, acc<[u64]>, swaps<u64>)
  └ :Done(arr<[u64]>).

#bubble-sort(arr) → :Pass(arr, [], 0)
  -- Pass: compare adjacent elements and rebuild list in acc
  :Pass([a, b | tail], acc, swaps)
    ├ a > b → :Pass([a tail], [b acc], swaps + 1)
    └ *     → :Pass([b tail], [a acc], swaps)
  :Pass([x], acc, swaps) → :Next([x acc], swaps)
  :Pass([], acc, swaps)  → :Next(acc, swaps)
  -- Reverse the accumulator to restore order
  :Next(arr, swaps) → :Reverse(arr, [], swaps)
  :Reverse([x | tail], acc, swaps) → :Reverse(tail, [x acc], swaps)
  :Reverse([], acc, 0)     → :Done(acc)
  :Reverse([], acc, swaps) → :Pass(acc, [], 0)
  :Done(arr) ⇒ arr.

a<[u64]> := [4 2 1 3]
sorted := #bubble-sort(a)
sorted! := sorted === [1u64 2u64 3u64 4u64]
sorted! / true

06 /

Notices + feedback

Each established notice role keeps its own pastel accent and its original icon: information, warning, success, error, idea, and question.

Information. The runtime keeps reactive values synchronized after each accepted input.

Warning. This host capability can write to resources outside the current module.

Success. The project built successfully and all required machines were resolved.

Error. The matrix dimensions do not match the function's declared input kind.

Idea. Wrap repeated transformations in a function to keep the model legible.

Question. Should this value be provided by the host or derived inside the program?
