# Activation-current forward read windows

IR264 extends the existing immutable child-window versioning beyond its original
paired forward/reverse restriction. Paired selection retains priority. A forward
group must contain only non-writable, non-appending views, share the same current
induction/count coordinates, pass the existing recurrence/scope proof, and prove
an additional source branch or read check before code is duplicated.

The existing entry gate checks the complete current interval. Each original
visit still selects its induction bound. Refusal enters the unchanged checked
child, including zero-trip, overflowing coordinates, default values, source
errors, finite work, publication and retry. No check is unconditionally removed
and no persisted layout or type grants memory access.

Tests require real one-view and two-forward-view versions in original/decoded
Objects, refuse a changing bound, compare ordinary/native/restored execution
through errors and fresh recovery, retain external aliases and output atomicity,
and exercise every existing finite boundary. The older paired-window tests and
all scalar/DEFLATE controls remain required.

The current hot related-post query has 14 ordinary capture reads and no guarded
loop window/version entry gates. A new compiler build must show whether this
extension reaches that query. Passing a synthetic proof fixture or reducing
static code is not evidence of a benchmark speedup.

The first IR258 attempt proves a real two-forward-view gate but its one-view
fixture is rejected before window analysis: an unused retained flat-frame array
blocks numeric entry. IR259 permits the existing opaque forwarding proof when
another array has a real immutable content witness. Unused owners retain zero
width and no read/write/append permissions. Purely opaque flat carriers keep the
efficient scalar path. The source/alias-version proof and the rejection of
unwitnessed content effects remain mandatory. Original failed receipts and
test-only diagnostic traces remain; no mechanism assertion is weakened.

The next IR259 attempt admits the single-view numeric tree, but the flat phase
adapter independently rejects its opaque owner and loses the complete child
scope needed by window analysis. IR260 carries the same strictly zero-permission
owner through that adapter and its original must-current source/exit proof. A
real immutable content witness is still required; any unwitnessed content effect
still rejects. No unread owner acquires a pointer, length or write permission.

An exact-current diagnostic shows the remaining one-view window is discovered
and proves one predicate/four additional source successors. The original
two-predicate profitability floor still rejects it. IR261 uses a one-predicate
floor for the forward family while preserving the paired floor, two-successor
minimum and requirement for a newly proved source branch/read check. All safety
proofs and the original positive, changing-bound and finite tests remain.

IR261 passes both one- and two-view positive assertions and both semantic/finite
contracts, but the purely opaque negative fixture still selects an outer numeric
phase. Its retained `sequence/length(nodes)` supplies a width/witness without
reading an element. IR262 consequently tests the selected actions for an actual
immutable `Read` before admitting flat opaque forwarding. The negative fixture
and its direct-scalar assertion are unchanged; the failed IR261 receipt remains.

The separate D5 diagnostic records the real hot posting loops (headers1341 and
1553): the selected `at<end` relation and checked `at+1` expression both survive.
Discovery ran only at explicit U64Lt operations, so it never inspected these
implicit reads. IR263 discovers the same current interval at an immutable read,
using the shared mathematical one-based-index decoder. A zero-offset forward
window admits `end<=length`; the visit must still select the exact current
`at<end`. Arbitrary loaded indices, changed bounds and wrong owners do not match.
Forward version selection now accepts a new proved read without requiring two
extra source branches. The paired-view profitability floor is unchanged.
New positive/negative source coverage, the same source/native error/alias/retry
checks and finite-boundary tests cover direct reads as well as guarded reads.

D6 discovers the real posting-read windows in20 independent analyses, but every
candidate is discarded because its count home is written. At the corresponding
ordinary latch, every candidate count retains exactly `Initial(its_home)`. IR264
uses that post-copy identity at every reachable ordinary backedge, independently
of the proposed window. Joins which change the value lose identity and decline;
no stable value is inferred from storage reuse or from the optimized path. The
proof does not cross a latch. Selected-window analysis performs one extra bounded
ordinary traversal (no window assumptions; maximum recursive depth two).
The new maintained source contract exercises invariant carrier copies for one
and two direct-read views; the complete semantic/finite tests include both.
Changing-bound refusals remain unchanged.

The first IR264 fixture did not preserve its bound on every backedge: `Try`
carried it while terminal `Done` erased the field. That original source remains
as an explicit conservative-refusal case. The positive fixture now carries the
unchanged field through both variants, matching the implemented all-backedge
identity contract. Separate CLI emissions confirm both real hot-query gates and
both all-backedge fixture gates. No benchmark source changed. Source/native
errors, aliases, recovery and finite budgets cover all eight guarded, direct,
invariant-carried and terminal-discarding source variants. A future active-only
recurrence proof may admit terminal erasure; the current proof does not assume it.
