# Activation-current forward read windows

IR258 extends the existing immutable child-window versioning beyond its original
paired forward/reverse restriction. Paired selection retains priority. A forward
group must contain only non-writable, non-appending views, share the same current
induction/count coordinates, pass the existing recurrence/scope proof, and prove
an additional source branch or read check before code is duplicated.

The existing entry gate checks the complete current interval. Each original
visit still selects its induction bound. Refusal enters the unchanged checked
child, including zero-trip, overflowing coordinates, default values, source
errors, finite work, publication and retry. No check is unconditionally removed
and no persisted layout or type grants memory access.

Tests require real one-view and two-forward-view versions in original/decoded
Objects, refuse a changing bound, compare ordinary/native/restored execution
through errors and fresh recovery, retain external aliases and output atomicity,
and exercise every existing finite boundary. The older paired-window tests and
all scalar/DEFLATE controls remain required.

The current hot related-post query has 14 ordinary capture reads and no guarded
loop window/version entry gates. A new compiler build must show whether this
extension reaches that query. Passing a synthetic proof fixture or reducing
static code is not evidence of a benchmark speedup.
