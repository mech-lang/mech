# Gate E1 teardown log

This is the working handoff log for the forward-only E1 teardown. It records
what was removed, which retained v0.4 capability was checked before removal,
and what a subsequent hardening round still needs to inspect.

## Decision rule

- A surface with no resident owner is deleted with its callers, wrappers,
  tests, configuration, exports, and implementation.
- E1 does not invent resident semantics to preserve legacy-only behavior.
- A deletion stops only when it would break an explicitly retained v0.4
  resident capability: source or bytecode execution, native/WASM/browser
  routing, capability enforcement, resident external effects, replay, or an
  established shipping host.

hardening round. They are not requests to restore legacy behavior.

- Resident source/bytecode planning checks `max_source_bytes` before compilation
  or decoding but does not charge the artifact, compiler working set, or source
  buffer against `max_memory_bytes`. The deleted interpreter test charged only
  its copied input string, so it was not equivalent resident coverage. E2 must
  define which resident planning/activation owner accounts bounded memory and
  add a product-level assertion at that owner.
- The production compiler rejects a top-level addressed assignment with
  `AddressedAssignmentUnsupported`, and rejects a context send inside an
  activation block with `ActivationScopeContextSendUnsupported`. Ordinary
  top-level sends compile, preflight once, embed the provider's transactional
  contract, and perform no delivery during planning. E2 should decide whether
  either rejected form belongs to the retained v0.4 language surface; E1 has
  deleted only their planning-mode interpreter wrappers.

  runtime host calls as a separate non-source surface.

  still construct its container with `.planning()` to prove compilation does
