# Private numeric result lifetime

A selected checked unsigned replacement or append may produce an unpublished
private result instead of publishing a canonical result that is immediately
consumed. Both result forms share the operation's existing validation, index
mapping, changed comparison, copying, capacity admission, and work charges.
This changes the result boundary, not the operation or its ownership proof.

## One representative writable recurrence

The native same-plan proof identifies the selected write and its current carrier
field. The first actual change closes the synchronous native loan and transfers
the carrier's owner to the original checked leaf. Core still decides whether
that input can be consumed. Live aliases, other imports and retained snapshots
keep the existing copy route; weak identities can never identify reused data.

The leaf constructs the final shape/data/root owners once. It confines that
fresh, unadmitted value directly to `PrivateUnsignedMatrix`. This boundary
requires exclusive root and data owners, including absence of weak observers,
a plain packed unsigned kind, and absence of an existing admission or physical
ticket. It retains the original complete byte and node witness, acquires the
current account's registration, and exposes no canonical value or weak identity.
Fingerprint caches are invalidated before private mutation.

The runtime retains its original post-leaf metadata work and capacity admission.
For an append, it then attaches the same previously admitted row-shape
preparation at the original handoff point. Moving the private owner between
these internal phases moves metadata only. Repeated writes inside the admitted
capacity use the same typed cells and the same final publication owners.
`finish` installs the pre-admitted registration and returns that owner without
allocation. Abort destroys the unpublished cells and releases their claims.
No new permission, account cache, planner, ABI or image proof is introduced.

## Materialization inventory for this path

| Boundary | Consumer and lifetime | Representation requirement |
| --- | --- | --- |
| Incoming carrier field | Selected checked operation; other carrier/arena roots and external aliases may retain old contents | Existing canonical input remains immutable unless Core's consuming transfer succeeds |
| Copied or consumed updated cells | Private recurrence, with one final result at reconciliation | Typed backing plus one pre-admitted final owner; no separately registered intermediate snapshot |
| Append row-shape preparation | This private phase and final length reconciliation | Existing admitted shape scratch, independent of the number of appends |
| Array reconciliation | Ordinary frame consumers after the native region, which can include unoptimized operations and retained call results | Canonical final owner remains necessary at this existing boundary |
| Scalar result | Existing native scalar/frame transport | No per-cell canonical materialization inside the recurrence |
| Private owner-slot workspace | One active numeric region per invocation | Current implementation still reconstructs sequential-region vectors; reuse is a separate remaining task |

This inventory establishes one removed boundary. It does not prove that all
region exits need canonical ownership, or inventory the full compressor's
constructors, constants, and retained results. Continuing private ownership
across further regions requires a separate current-liveness and consumer proof.

## Resource and failure behavior

The selected leaf's finite limits, metadata envelopes, output/clone limits,
source charges, and copy/consume decision remain unchanged. The final private
owner retains the same conservative canonical byte/node witness. The runtime's
post-leaf metadata admission and append-preparation attachment stay ordered as
before. All fallible preparation finishes before mutable cells are exposed or
external outputs are published.

The removed representation previously performed an import, released its node
claim during consumption, then allocated and admitted another owner. The new
owner retains one claim continuously. No allocator request or import-failure
sentinel is synthesized for the deleted registration or lock. The fixture that
fails the Nth real import allocation therefore refers to a different later
allocation after this removal; that historical ordinal is not a resource-policy
contract. Required finite admission and error/publication/retry behavior are
qualified independently. Logical work pricing is unchanged.

## Acceptance evidence

Qualification must cover original/decoded compiled recurrences, delayed first
changes, multiple arrays, retained aliases, failures before and after the
selected operation, unchanged prior publications, cleanup and retry. Core
controls cover all four unsigned widths, real tree/cache sizes, stale token
invalidation, weak/strong observer rejection, exact byte/node limits and
allocation denial. A compiled allocation witness varies recurrence visits
within a fixed backing capacity; a successful lifetime has no allocation slope
per additional private update. Counts, instructions, elapsed time and memory are
reported separately for complete small-input compression. Allocation parity is
not inferred from this single boundary change.
